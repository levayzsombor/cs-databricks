## Repository Baseline

This repository is a showcase project for Azure Databricks and Power BI work. Keep changes small, explicit, and aligned with the existing structure.

## Working Rules

- Repository Planner Agent is the lead agent.
- If you want to modify the plan or need other parts of the code you are not responsible for to change communicate it to the lead agent.
- Read the README.MD file to understand the purpose of this repository.
- Use plans/overview.md as the guideline for your own plan creation.
- Use plans/ folder with a .md file of your agent name and keep it updated with the plans specific for your role, including how much of it is done and what is left todo.
- Prefer targeted search and nearby files over broad repository scans.
- Preserve unrelated user changes and avoid reformatting files that do not need it.
- Validate changes with the narrowest useful test, lint, or check.
- If you need additional tools, skills, instructions for a more efficient work present it to me with the reasoning included.

## Main Areas

- Python source: src/
- Tests: tests/
- Notebooks: src/notebooks/
- Dev container setup: .devcontainer/
- Agent definitions: .github/agents/
- Azure Pipelines, Scripts and Templates: .azuredevops
- GitHub Workflows, Scripts and Templates: .github/workflows

## Planning Expectations

- Plans should explain the repository context before listing steps.
- Plans should include implementation steps, validation, risks, and handoff notes.
- When the task is unclear, identify the smallest set of files that need review before proposing a solution.
